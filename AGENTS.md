# AGENTS.md

Guidance for AI coding agents and contributors working in this repository. `CLAUDE.md` is a symlink to this file.

## What this is

iOS SSH terminal + VNC app (SwiftUI, iOS 17+) for managing tmux-based agent sessions from iPhone. Companion watchOS app and home/lock-screen widget. Commits use conventional format (`<type>(<scope>): <subject>`).

## Commands

```sh
./Scripts/build-libghostty.sh                      # build the pinned libghostty-vt xcframework (zig) into Packages/Core/Frameworks; required once before any build or test
xcodegen generate                                  # regenerate pocketshell.xcodeproj (required after project.yml edits; .xcodeproj is gitignored)
swift test --package-path Packages/Core            # all unit + sshd integration tests (fast, no simulator)
swift test --package-path Packages/Core --filter TmuxKitTests            # one test target
swift test --package-path Packages/Core --filter TabStatusResolverTests/holdsPreviousStatus  # one test
PS_SONIOX_LIVE_KEY=<key> swift test --package-path Packages/Core --filter SonioxLive  # opt-in live Soniox measurements (bills per use)
swift build --package-path Packages/Core           # compile check without tests
./Scripts/unittest-ios.sh                          # App unit tests (pocketshellTests) + Core package tests on the iOS simulator
./Scripts/uitest.sh                                # e2e UI tests: throwaway sshd + tmux session + simulator
xcodebuild build -scheme pocketshell -destination "generic/platform=iOS Simulator"  # full app build
pre-commit run --all-files                         # format + lint + Core tests (hooks: pre-commit install)
./Scripts/install-mac.sh                           # build + install the Catalyst app into /Applications on this Mac
./Scripts/ship.sh                                  # archive iOS + Catalyst and upload both to TestFlight
```

- libghostty-vt is a gitignored binary target: `Scripts/build-libghostty.sh` pins the Ghostty commit, applies `Scripts/libghostty-*.patch` (x86_64 simulator and Catalyst slices — Zig 0.17 OS tag `maccatalyst` — plus keeping the top rows when the alternate screen shrinks), and needs `zig` (Homebrew, ≥ 0.17). Its Zig dependencies come from `deps.files.ghostty.org`, `github.com`, and `codeberg.org`. Set `PS_LIBGHOSTTY_BUILD`/`ZIG_GLOBAL_CACHE_DIR` to keep build output and caches off the internal disk, `PS_GHOSTTY_SRC` to reuse a local Ghostty clone.
- Warnings are errors everywhere: `SWIFT_TREAT_WARNINGS_AS_ERRORS` in `project.yml`, `.treatAllWarnings(as: .error)` in `Package.swift`. Any warning fails the build.
- Formatting is enforced by toolchain `swift format` via pre-commit (`.swift-format`: 4-space indent, line length 120). Run `swift format --in-place --recursive <paths>` before committing if hooks are not installed.
- Coverage: `swift test --package-path Packages/Core --enable-code-coverage`, then `xcrun llvm-cov report "$(swift build --package-path Packages/Core --show-bin-path)/CorePackageTests.xctest/Contents/MacOS/CorePackageTests" -instr-profile "$(swift build --package-path Packages/Core --show-bin-path)/codecov/default.profdata" -ignore-filename-regex='(Tests|checkouts)'`.

## Shipping

- `Scripts/ship.sh` refuses a dirty tree and sets `CURRENT_PROJECT_VERSION` to minutes since 2020, which only ever climbs. Do not go back to `git rev-list --count HEAD`: rewriting history lowers the count and App Store Connect permanently rejects a reused build number.
- All three Info.plists take their versions from `$(MARKETING_VERSION)`/`$(CURRENT_PROJECT_VERSION)`; bump `MARKETING_VERSION` in `project.yml` for a user-visible version, never edit the plists directly (xcodegen rewrites them).
- The watchOS app and widget ride along inside the iOS archive. The Catalyst build uploads as a separate macOS build of the same app record.
- **Catalyst must be sandboxed to upload** (`90296`), so the app and widget carry `CODE_SIGN_ENTITLEMENTS[sdk=macosx*]` pointing at separate `*-mac.entitlements` files; iOS keeps the plain ones. The Mac needs `network.client` for SSH/VNC, `network.server` because `PortForwarder` binds a local listener, and `files.user-selected.read-write` for the config import/export in Settings. Sandboxing moves `UserDefaults.standard` into the app container, so a Mac install made before this loses its UI preferences once — hosts and snippets live in the app group and credentials in the Keychain, both unaffected.
- App Store keys live in `project.yml`, not the plists: `LSApplicationCategoryType` (required for the Mac build), `CFBundleDisplayName` on the widget (Apple rejects an extension without one, `90360`), and `App/PrivacyInfo.xcprivacy` declaring `NSPrivacyAccessedAPICategoryUserDefaults`/`CA92.1`. Missing the manifest fails upload with `ITMS-91053`.
- **Do not set `ITSAppUsesNonExemptEncryption`**: with `true` and no compliance code filed, every upload dies on `90592` ("Invalid Export Compliance Code … key value []"); `false` would be a false claim, since SSH/VNC ships its own crypto rather than only calling Apple's. Omitting the key lets the build upload and moves the question to App Store Connect, one answer per build. Before any public release the encryption still needs a self-classification report (BIS ERN) plus the French declaration.

## Testing

- SSHKit integration tests are `#if os(macOS)`: they spawn a real `/usr/sbin/sshd` on a random localhost port (`TestSSHD` in `SSHConnectionIntegrationTests.swift`) and run as part of plain `swift test`. Never call `Process.waitUntilExit()` in tests: it waits on a run loop that a Swift concurrency thread never wakes, and hung whole `swift test` runs; poll `isRunning`. Watchdogs that outlive a parent must treat a zombie (`ps -o stat=` `Z`) as dead — `kill -0` succeeds on an unreaped pid.
- `Scripts/uitest.sh` generates a client key (`Scripts/gen-test-key.swift`), starts a throwaway sshd plus a detached tmux fixture session, and passes `PS_TEST_KEY`/`PS_TEST_PORT`/`PS_TEST_USER`/`PS_TEST_TMUX` into the UI tests via `TEST_RUNNER_` env vars. Tests skip themselves if those are unset. Simulator defaults to iPhone 17; override with `PS_TEST_SIM` (and `PS_TEST_SIM_OS` to pin its runtime), falls back to first available iPhone.
- UI tests in `UITests/SmokeUITests.swift` are order-dependent (XCTest runs alphabetically): `testAddHostAndRunExecSnippet` creates the `localbox` host that later tests reuse.
- `Scripts/unittest-ios.sh` runs the app-hosted `pocketshellTests` target (`AppTests/`, `@testable import pocketshell`, swift-testing) then `Core-Package` on the iOS simulator and again on Mac Catalyst (`platform=macOS,variant=Mac Catalyst`, no simulator; `PS_TEST_SIM`, default iPhone 17 Pro; DerivedData under `PS_BUILD_DIR`, default `./DerivedData`), so it covers `#if os(iOS)` and `#if targetEnvironment(macCatalyst)` Core tests (guard iOS-only behavior with `#if !targetEnvironment(macCatalyst)`). It skips `KeyKitTests`: a host-less package test bundle has no Keychain entitlement on the simulator (-34018); macOS `swift test` covers them. App logic tests go in `AppTests/`; the test target has no direct Core package deps (linking SSHKit twice breaks the link), so reach Core types through the host app.
- UIKit-gated sources (`TerminalBridge`, `SSHTerminalView`, VNC views, `TerminalToolbar`) do not compile into macOS `swift test` — cover them with `#if os(iOS)` tests in the Core package (run by `Scripts/unittest-ios.sh`) or UI tests. Terminal screen content is not accessibility-visible (the Metal renderer draws it), so e2e asserts toolbar presence and absence of error text, not screen text.
- New tests: unit tests go next to the module in `Packages/Core/Tests/<Module>Tests/`; e2e flows go in `UITests/SmokeUITests.swift` with an accessibility identifier on any new tappable control.
- Every feature and bug fix needs regression coverage at the narrowest viable layer. Do not commit an implementation without a test that fails when the behavior regresses.

## Architecture

Thin app targets, all logic in `Packages/Core` (local SPM package, one library per concern):

- **Models** — value types shared by every target (Host, Snippet, SessionSnapshot, ConfigExport, themes, toolbar keys, VNC config, voice Live Activity state). Watch + Widget depend only on this.
- **KeyKit** — Secure Enclave P-256 device key with software Keychain fallback, OpenSSH public/private key encoding (incl. bcrypt-pbkdf for encrypted keys), password vault.
- **SSHKit** — swift-nio-ssh connection, TOFU known-hosts store, port forwarding, SFTP session, chunked-base64-exec remote file upload. Depends on KeyKit + SFTPKit.
- **SFTPKit** — pure SFTPv3 packet encode/decode (no IO).
- **TmuxKit** — tmux command building and output parsing (session/window/pane listing, dashboard previews, send-keys).
- **MonitorKit** — `TabStatusResolver` (busy/idle/needs-input from screen-text diffs), `AgentActivityTracker` (agent-finished notifications), and `AgentPermissionSwitch` (Skip Permissions: restart Claude with `--dangerously-skip-permissions`, Codex Full Access).
- **ReconnectKit** — auto-reconnect state machine with backoff.
- **VTKit** — Swift wrapper over the libghostty-vt C API (`GhosttyVt` binary target): feed/resize, viewport snapshots with dirty rows, modes, scrollback, selection and NUL-free copy, key/mouse/focus encoders, `CursorAddressTracker` (the explicit-CUP signal libghostty lacks), `CaretSettleGate`/`CaretController`.
- **TerminalUI** — `SSHTerminalView` hosts `GhosttyTerminalView` (VTKit terminal drawn by a Metal renderer over a shared CoreText glyph atlas, `Ghostty/`) with `GhosttyGestureCoordinator` for touch, pointer, and selection; `TerminalBridge` connects it to the SSH session. Also feed gating, font zoom, pan/scroll tracking, IME composition overlay.
- **ToolbarUI** — special-keys toolbar, key-sequence encoder, user-editable via `toolbar.json`.
- **VNCKit** — RoyalVNCKit session controller, screen view, pointer math, key combos (ARD auth).
- **LockKit** — Face ID app lock gate.
- **BrainKit** — voice conversation ("voice brain"): streaming OpenAI-compatible Chat Completions client (SSE, tool calls assembled from deltas), per-host `Conversation` memory (1h resume, bounded history, cut to the heard text on barge-in), `TurnTaking` state machine (barge-in, 2s filler, 1.5s proactive silence; injected clock), `EchoGuard`, `AgentToolbox` + `HostAgents`/`AgentTranscript`/`AgentControl` (agent list, transcript answers, keys and prompts over SSH exec), `ConfirmationGate`/`SafetyPolicy`, `AgentEventQueue`, and the `VoiceBrain` orchestrator. Ears and mouth are VoiceKit protocols (`VoiceEars`/`VoiceMouth`): `OnDeviceEars`/`SystemMouth` on the iPhone, `SonioxEars`/`SonioxMouth` in the cloud, each wrapped by `FallbackEars`/`FallbackMouth`. The brain streams raw reply tokens into the mouth (`stream`/`finish`); the mouth cleans them (`SpeechCleaner` for token streams, `SpeechChunker` for whole sentences) and reports `.upcoming` and `.heard` text. `TurnTiming`/`BenchmarkLog` time every turn; `TurnAudioArchive` keeps user speech for offline benchmarks.

`App/` is SwiftUI glue: screens, stores, `ConnectionController` (owns SSH lifecycle per host), `SessionMonitor` (5s polling), `WatchRelay` (WatchConnectivity). `WatchApp/` and `Widget/` are separate targets sharing app group `group.com.bl4ko.pocketshell`.

New code goes in a Core module with tests, not in `App/`, unless it is pure UI glue.

## Hard-won gotchas (do not re-learn)

- **Agent diagnostics run inside a sandbox**: filesystem, process, Keychain, network, and Unix-socket visibility can be restricted even when a command itself runs. A failed socket query can make a live daemon look stopped (Herdr `session list` reported `running: false` when its socket was inaccessible). Before diagnosing external state from a permission error or suspicious negative result, rerun the smallest read-only check with the required approval outside the sandbox.

- **Every tmux `set-option` in the attach chain needs an explicit `-t <clone>`**: the chain runs before the client has attached, so an untargeted `set-option` has no current session to resolve against and lands either nowhere (clones never expire — they piled up one per tab ever opened) or on the whole server. Server-wide is destructive: `destroy-unattached on` then kills every detached session and the server exits with it, and `status off` stops tmux-continuum saving, because continuum drives its periodic save off status-line redraws. Order matters too — `destroy-unattached` must be set *after* `attach-session`, since `new-session -d` leaves the clone unattached and tmux destroys it the instant the option lands. Commands after `attach-session` in the same `\;` sequence do run. `cleanupClonesCommand` sweeps leftovers on connect but only kills `*-psh-????????` sessions that are unattached, **grouped**, and >60s old: grouped means the windows are shared with the session they clone so nothing is lost, the age guard avoids racing a tab mid-connect, and a same-named session restored by tmux-resurrect is standalone and holds the only copy of its panes. Verify tmux behaviour on a private socket (`tmux -L pshtest`) — never against a real server.
- **A stale standalone `*-psh-????????` session must not outrank its live base session**: tmux-resurrect can restore an old clone as a separate one-window session while the real base (for example `homeops`) is also present. `consolidateGroups` and `canonicalSessionMap` collapse that stale alias onto the base; `SessionMonitor` then repairs saved tab sessions, matching clone-named tab groups, and the host's configured default session. Without all three repairs, an older device can open the standalone clone and sync a one-tab layout over the real workspace.
- **An ended tmux attach is a reconnect, never a tab closure**: a bad/stale target or transient tmux command exit used to call `onExit`, and `HostTabsScreen` interpreted that as an explicit close, persisted the deletion, then synced it to every device. `ConnectionController.handleStreamEnded` routes tmux exits through `ReconnectMachine`; only a deliberately exited plain shell may auto-close its tab.
- **Tab status detection**: `TabStatusResolver` trusts explicit busy/waiting/idle markers; screen diffs are not activity because idle TUIs redraw and busy TUIs can stay static. Tmux polling captures `pane_current_command` with the screen: markerless redraw frames hold the previous status while a foreground process runs, and returning to an interactive shell clears it. Non-tmux tabs retain a one-frame markerless grace. Busy→idle needs 2 consecutive idle frames (`pendingIdle`): Claude Code emits transient idle-marker frames mid-session (survey screen, auto-mode gaps — footer markers like "shift+tab to cycle" and the `\d+% used` ctx statusline read as confident idle while the spinner is absent), which faked finished-unseen dots. Codex idle is detected via `\d+% (context left|used)` footer regex. The running-task/spinner busy marker is `\S…\s*\(\d+[hms]` — it was `\p{L}…` and any task label ending in `)`/digit (e.g. "…(blocked on user Apple portal)… (4m 57s · ↓ 8.5k tokens)") read as confident idle mid-run, faking the finished dot. `pollTabs` feeds `AgentActivityTracker` (and its finished/needs-input transitions) **only non-tmux tabs**, so any per-tab UI signal that must also cover tmux-attached agent tabs has to derive from per-tab status history, never from tracker transitions. The finished-but-unseen blue dot lives in `SessionMonitor.unseenFinished` (keyed `hostID:session:windowIndex`) because `HostTabsScreen` state dies on navigation — it is fed by both the monitor's 15s idle transitions and the 5s tab poll (compare `lastTabStatus`, which ignores nil frames), cleared by viewing the tab or the window going busy, and drives tab-to-front promotion plus the hosts-list blue dot.
- **tmux `window_name` can be a transient placeholder**: automatic-rename rewrites it to `[tmux]` while the pane is in copy mode (any attached client scrolling does it) and `[dead]` after the pane dies. Never persist or display those raw — `Tmux.isPlaceholderWindowName` filters them, `Tmux.windowDisplayName` resolves notification/snapshot names via saved `TabRecord`s (user `name` first, then non-placeholder `windowName`), and `pollTab` refuses to overwrite `tmuxWindowName` with a placeholder. Same trap produced a "bl4ko homeops:4 [tmux]" notification for a window the user had named. Also: a workspace pushed by a device that hasn't polled yet carries nil names — `TabRecord.preservingNames` merges remote over local without wiping known names, else every host open flashes bare tab numbers until the first pane poll. Notifications for the currently-viewed window are suppressed via `SessionMonitor.visibleWindowKey` (set by tab selection/poll, cleared on disappear/background so background notifications still fire).
- **Do not anchor `confirmationDialog` to toolbar chrome on iOS 26**: it renders as an arrow popover pinned to a wrong mid-screen anchor with broken animation, and the stuck presentation can leave nav-bar buttons unresponsive afterwards. The host switcher is a toolbar `Menu` instead — correct anchor, native animation, same buttons for XCUITest.
- **A custom long-press gesture kills `.contextMenu` on the same view**: the tab strip's 0.28s reorder long-press claims the touch before the system context-menu interaction fires, so the tab menu silently died on iPhone. Pair the gesture with a simultaneous longer still-hold (0.55s, context-menu timing) that presents the same actions as a `confirmationDialog`; movement past the reorder threshold cancels it via the `draggingTab` guard. `.contextMenu` stays for Catalyst right-click.
- **Host toolbar items hide their Liquid Glass capsule** (`withoutGlass()`, `sharedBackgroundVisibility(.hidden)`): the glass re-tints against the terminal content behind and around it — even 60pt away — so the back/options/new-tab buttons flashed grey whenever terminal content moved, e.g. during the keyboard slide. Hiding the edge effect, moving the slide to `visualEffect`, or a UIKit transform did not help; only removing the adaptive capsule did. Guarded by `testTopBarButtonsHaveNoAdaptiveGlass`.
- **Max three trailing toolbar items on iOS**: a fourth goes into the system overflow menu, which on iOS 26 renders its "…" button but does not open — the item is effectively gone (this hid new-tab). Consolidate into the ellipsis `Menu` instead.
- **UI tests run against a real user home**: `uitest.sh`'s throwaway sshd authenticates as the developer, so the app under test reads/writes the real `~/.config/pocketshell/workspace.json` — test runs once pushed 15 throwaway numbered tabs that every attached device then restored. `SessionMonitor.syncWorkspace` is a no-op under `PS_UI_TEST=1`; keep any future per-host remote state behind the same guard.
- **Hidden tabs** live in a ZStack: `allowsHitTesting(false)` blocks touches but NOT first responder. Tab switch focuses the selected TerminalView; `becomeFirstResponder` auto-resigns the old one — never resign-then-become (keyboard dismiss/present jank). `.opacity(0)` does not stop rendering: every hidden tab redrew whenever `FeedGate`'s 1s flush delivered buffered output (11 tabs once cost 1.0G of CoreAnimation memory). `TerminalBridge.suspendRendering` hides the **layer** of a non-live tab — `view.isHidden` would resign first responder, `layer.isHidden` does not — and `GhosttyTerminalView.setRenderingSuspended` also shrinks the Metal drawable to 1×1 and pauses the display link; `setNeedsDisplay` on unhide restores the drawable and repaints. Background tabs still parse their feed, so status polling and scrollback are unaffected. Guarded by `hiddenTabsSkipRenderingAndRepaintWhenShown`.
- **Keyboard bottom padding** applies to the ACTIVE tab only and without animation — animated padding reflows the terminal every frame on every tab (lag + PTY resize storms).
- **The keyboard's Liquid Glass tints from whatever is behind it**: the layout padding commits only after the show motion (and drops before the hide motion), so the area behind the keyboard switched from the dark terminal to the light `paper` mid-toggle and the keyboard flashed grey→white. `TerminalToolbar` paints its `pinned` colour 1000pt down behind the keyboard so that area never changes. Guarded by `testKeyboardToggleKeepsToolbarColorBehindKeyboard`.
- **Full-screen apps do not slide with the keyboard**: shell content rides up with the keyboard so the prompt stays visible, but a full-screen app (alternate screen: Herdr, tmux, vim) redraws for the new size anyway, so sliding pushed its header off the top and the redraw snapped it back. `TerminalScreen` decides once per motion from `TerminalBridge.isFullScreenApp` and only clips those (Herdr and tmux are the exception, see the next entry). `Scripts/libghostty-alt-shrink.patch` keeps the top rows when a scrollback-less (alternate) screen shrinks — upstream keeps the cursor row, which dropped the header until the app redrew. Guarded by `testKeyboardToggleKeepsFullScreenAppStill`, `AltScreenResizeTests`, and `shrinkingFullScreenAppKeepsHeader`.
- **The keyboard never resizes a Herdr or tmux terminal**: each height change made Claude Code inside the multiplexer reprint its long streaming answer — its erase-and-rewrite cannot reach rows that scrolled away, so a second copy landed in Herdr's own pane buffer (`herdr pane read` shows it; PocketShell replays Herdr's resize diffs correctly). With `isMultiplexerAttached`, `followKeyboard` keeps the layout inset at 0 and slides the content only as far as `KeyboardSlide` needs to keep the parked caret plus 3 rows (Claude Code's box border and footer) above the keyboard — a full-height slide pushed a fresh Claude Code prompt at the top off screen. The park is `CaretController.parkedRow`, which tracks the cursor even while hidden (Claude Code hides it but parks it on its input line) and never the mid-repaint cursor; the slide grows as the caret moves down and shrinks only when the caret would leave the visible top, so repaints never bounce it. Other full-screen apps still clip and resize. Herdr does not clear on resize: it diffs against its own model of the old screen, which assumes the terminal keeps the top rows (the alt-screen shrink patch). Guarded by `testKeyboardKeepsHerdrTerminalSize`, which also taps the tab strip so the slid terminal must not swallow touches above it.
- **The automatic arrow panel must not react to its own resize**: `ArrowPrompt` opens the arrow panel when a selection footer is in the last 6 rows, but the panel was 260pt against a 308pt system keyboard (and still differs before the first typing keyboard is measured), so the terminal grew. An app that keeps its footer on a fixed row (Claude Code inside Herdr) then sits above that window, the prompt read as gone, the keyboard came back, the terminal shrank, the footer re-entered the window — panel and keyboard swapped by themselves every ~1.3s. Detection opens on the last 6 rows but, once open, holds while any 6-row window on screen still has the footer. Guarded by `keepsPromptWhenThePanelGrowsTheTerminalBelowIt` and `testTerminalArrowsStayWhenThePanelGrowsTheTerminal` (`arrow-prompt pinned`).
- **The shortcut panel takes the typing keyboard's height**: an input view of another height resizes the PTY on every panel/keyboard swap, so full-screen apps (Herdr) redraw and jump. `TerminalViewController` records the last visible typing-keyboard height (`keyboardDidChangeFrame` while `inputView == nil`, ignoring the <150pt hardware-keyboard bar) in a static shared by all tabs and sets `shortcutInput`'s frame height before each swap. A `UIInputView`'s frame height is the whole keyboard frame, home-indicator area included. Equal heights break UIKit's tracking: swapping the panel back to the system keyboard posts only the panel's hide and no show (still true 1px apart), so `keyboardLayoutGuide` stays "hidden" with the keyboard on screen and the terminal grew under it. On that swap the controller publishes `TerminalBridge.keyboardHold`; `TerminalScreen` uses it only while the probe reads hidden, and it clears on the next swap to the panel or on `resignFirstResponder` (UIKit already thinks hidden, so a real hide then changes nothing the probe can see). Guarded by the equal-height and hide asserts in `testTerminalArrowPanelReplacesKeyboardAndClearsShift` and `testTerminalShortcutsReplaceKeyboardAndRememberCategory`.
- **Clipboard image paste** uploads to remote `/tmp/psh-*.jpg` via chunked base64 exec and inserts the path. Decode MUST be `base64 -d < file` (stdin redirect): BSD base64 on macOS remotes rejects a positional input file with exit 64, and the upload loop surfaces exec failures into the terminal. On Catalyst the toolbar (and its paste button) is compiled out; Cmd+V reaches `GhosttyTerminalView.paste(_:)`, which tries `pasteImage` before text, through a registered `UIKeyCommand`.
- **The toolbar paste is a system `PasteButton`, never a `UIPasteboard` read**: reading the pasteboard from a custom button makes iOS show "Allow Paste" on every tap (it also blocks the main thread until answered, which is why the e2e test once took 200s). `PasteButton` hands over `NSItemProvider`s with no prompt; `TerminalBridge.paste(_:)` uploads an image first, otherwise sends text. The edit-menu `paste(_:)` is system-trusted too and keeps its own image-first path. **Never wrap the `PasteButton` in `.contextMenu`**: the menu's press effect (`_UIGravityWellEffectAnchorView`) takes over any finger hold longer than ~0.2s, the control then sends no authentication message, and iOS prompts. XCUITest's instant `tap()` never triggers it, so the simulator test passed while every real tap prompted; the test presses for 0.25s instead. Copy and select mode open from a simultaneous 0.5s long press as a `confirmationDialog`. `pasted` logs why it allowed or prompted (`AuthMessageAuthentic`, `AuthenticationMessageMissing`, `ButtonLegible`, `ButtonTooFaded`, …): `xcrun simctl spawn <udid> log stream --predicate 'process == "pasted" AND category == "Pasteboard"'`. Guarded by `testTerminalClipboardButtonPastesTextAndImages` (asserts no prompt), `testTerminalEditMenuPasteDoesNotPrompt`, and `toolbarPasteUploadsAnImageBeforeText`.
- **Mac Catalyst installs must be development-signed**: never install a `CODE_SIGNING_ALLOWED=NO` build. An unsigned replacement loses the Team ID/app-group entitlements and cannot read PocketShell's Keychain SSH credentials. Use `Scripts/install-mac.sh` — Xcode never touches `/Applications`, so rebuilding there leaves the Dock icon on the old binary. Alternating `xcodebuild` and Xcode runs over one DerivedData also breaks signing: Xcode's incremental build re-signs only the embedded frameworks it rebuilt and skips `CodeSign` on `pocketshell.app` itself (its task looks up to date), so the app binary another build wrote stays unsigned and launching fails with "The executable is not codesigned". A clean build is the only way back; the install script detects the unsigned product and does that automatically.
- **RoyalVNC on Mac Catalyst uses our fork**: PocketShell pins `bl4ko/royalvnc` commit `7cd41cf` because upstream 1.1.0 fails to bridge `IOSurface` to `IOSurfaceRef` with Xcode 26.5. The one-line fix is upstream PR #36; keep the fork pin until it is merged and released, then verify signed Catalyst and iOS builds before switching back.
- **The caret must never render on a mid-repaint screen**: a busy TUI (Claude Code under load) writes each repaint in pieces with 80–120ms pauses and the cursor left *visible* mid-frame — tmux relays the pane cursor honestly, so the protocol itself says "cursor visible at the redraw anchor" (column 0 of Ink's dynamic-region top, the same cell every blip). No quiescence window separates a half-finished frame from a finished one; the reliable tell is **how the cursor got there**: finished frames park it with explicit CUP addressing, mid-frame pieces leave it dragged by text/newlines. VTKit's `CursorAddressTracker` (`VTTerminal.cursorAddressed`) tracks this and `CaretSettleGate` commits addressed row changes instantly, unaddressed ones only after 250ms of stream quiet; same-viewport-row moves (typing) always commit. That quiet fallback must run in tmux too: ordinary shell newlines are unaddressed, so suppressing it in multiplexer mode strands the caret on the previous row. During a `.wait` the caret stays painted at the last committed park — hiding it there was itself flicker, because a busy TUI hits the wait path on every repaint piece (~10Hz hide/show at the parked cell). Tmux also wraps full multi-pane redraws in `DECTCEM` hide/show; `CaretController`'s `hidePending` holds the painted caret through that transaction and trusts the matching show as the final park, including a legitimate column-zero cursor. Two prior gates failed: absolute-row stability (scrolling moves the true row every frame while repaints park on one cell — the wrong cell is the stable one) and plain 50ms quiescence (mid-frame pauses exceed it). Verified by replaying captured client streams through the emulator (`CaretStreamReplayTests`, capture via `ptycap` pty wrapper over a throwaway sshd — `pipe-pane` captures the wrong layer, and a locally attached client coalesces tmux's writes; only ssh-hop capture shows real chunking). Do not "fix" a caret complaint by touching caret coordinates — placement math is fine, timing is what breaks. The caret is always a steady block, focused or not, and remote DECSCUSR is ignored: blinking and mid-session style flips read as flicker (`caretStaysASteadyBlockWithoutFocus`).
- **libghostty-vt has no cursor-addressing flag or alt-screen top-row shrink**: VTKit scans the byte stream for the last cursor move (CUP/HVP addressed; text, C0 moves, CUU/CUD/CUF/CUB, CHA/VPA, IND/NEL/RI, DECRC not) and records DECTCEM hides per chunk for the caret gate; `Scripts/libghostty-alt-shrink.patch` makes a scrollback-less screen drop bottom rows on shrink. Both are covered by `VTKitTests` (`CaretStreamReplayTests` replays the busy-TUI capture, `AltScreenResizeTests`). Ghostty's own selection is installed in the terminal (`GHOSTTY_TERMINAL_OPT_SELECTION`) so it follows output; endpoints are inclusive.
