# CLAUDE.md

Guidance for AI coding agents and contributors working in this repository. `AGENTS.md` is a symlink to this file.

## What this is

iOS SSH terminal + VNC app (SwiftUI, iOS 17+) for managing tmux-based agent sessions from iPhone. Companion watchOS app and home/lock-screen widget. Commits use conventional format (`<type>(<scope>): <subject>`).

## Commands

```sh
xcodegen generate                                  # regenerate pocketshell.xcodeproj (required after project.yml edits; .xcodeproj is gitignored)
swift test --package-path Packages/Core            # all unit + sshd integration tests (fast, no simulator)
swift test --package-path Packages/Core --filter TmuxKitTests            # one test target
swift test --package-path Packages/Core --filter TabStatusResolverTests/holdsPreviousStatus  # one test
swift build --package-path Packages/Core           # compile check without tests
./Scripts/uitest.sh                                # e2e UI tests: throwaway sshd + tmux session + simulator
xcodebuild build -scheme pocketshell -destination "generic/platform=iOS Simulator"  # full app build
pre-commit run --all-files                         # format + lint + Core tests (hooks: pre-commit install)
./Scripts/install-mac.sh                           # build + install the Catalyst app into /Applications on this Mac
./Scripts/ship.sh                                  # archive iOS + Catalyst and upload both to TestFlight
```

- Warnings are errors everywhere: `SWIFT_TREAT_WARNINGS_AS_ERRORS` in `project.yml`, `.treatAllWarnings(as: .error)` in `Package.swift`. Any warning fails the build.
- Formatting is enforced by toolchain `swift format` via pre-commit (`.swift-format`: 4-space indent, line length 120). Run `swift format --in-place --recursive <paths>` before committing if hooks are not installed.
- Coverage: `swift test --package-path Packages/Core --enable-code-coverage`, then `xcrun llvm-cov report "$(swift build --package-path Packages/Core --show-bin-path)/CorePackageTests.xctest/Contents/MacOS/CorePackageTests" -instr-profile "$(swift build --package-path Packages/Core --show-bin-path)/codecov/default.profdata" -ignore-filename-regex='(Tests|checkouts)'`.

## Shipping

One machine builds and everything else installs from TestFlight, so only machines used for tethered debugging need registering at developer.apple.com.

- `Scripts/ship.sh` needs `ASC_KEY_ID` + `ASC_ISSUER_ID` exported and the App Store Connect key at `~/.appstoreconnect/private_keys/AuthKey_$ASC_KEY_ID.p8`. The key must have the **Admin** role — App Manager can upload builds but not mint signing assets, and export fails with "Cloud signing permission error". It refuses a dirty tree and sets `CURRENT_PROJECT_VERSION` to minutes since 2020, which only ever climbs. Do not go back to `git rev-list --count HEAD`: rewriting history lowers the count and App Store Connect permanently rejects a reused build number.
- All three Info.plists take their versions from `$(MARKETING_VERSION)`/`$(CURRENT_PROJECT_VERSION)`; bump `MARKETING_VERSION` in `project.yml` for a user-visible version, never edit the plists directly (xcodegen rewrites them).
- The watchOS app and widget ride along inside the iOS archive. The Catalyst build uploads as a separate macOS build of the same app record.
- **Catalyst must be sandboxed to upload** (`90296`), so the app and widget carry `CODE_SIGN_ENTITLEMENTS[sdk=macosx*]` pointing at separate `*-mac.entitlements` files; iOS keeps the plain ones. The Mac needs `network.client` for SSH/VNC, `network.server` because `PortForwarder` binds a local listener, and `files.user-selected.read-write` for the config import/export in Settings. Sandboxing moves `UserDefaults.standard` into the app container, so a Mac install made before this loses its UI preferences once — hosts and snippets live in the app group and credentials in the Keychain, both unaffected.
- App Store keys live in `project.yml`, not the plists: `LSApplicationCategoryType` (required for the Mac build), `CFBundleDisplayName` on the widget (Apple rejects an extension without one, `90360`), and `App/PrivacyInfo.xcprivacy` declaring `NSPrivacyAccessedAPICategoryUserDefaults`/`CA92.1`. Missing the manifest fails upload with `ITMS-91053`.
- **Do not set `ITSAppUsesNonExemptEncryption`**: with `true` and no compliance code filed, every upload dies on `90592` ("Invalid Export Compliance Code … key value []"); `false` would be a false claim, since SSH/VNC ships its own crypto rather than only calling Apple's. Omitting the key lets the build upload and moves the question to App Store Connect, one answer per build. Before any public release the encryption still needs a self-classification report (BIS ERN) plus the French declaration.

## Testing

- SSHKit integration tests are `#if os(macOS)`: they spawn a real `/usr/sbin/sshd` on a random localhost port (`TestSSHD` in `SSHConnectionIntegrationTests.swift`) and run as part of plain `swift test`.
- `Scripts/uitest.sh` generates a client key (`Scripts/gen-test-key.swift`), starts a throwaway sshd plus a detached tmux fixture session, and passes `PS_TEST_KEY`/`PS_TEST_PORT`/`PS_TEST_USER`/`PS_TEST_TMUX` into the UI tests via `TEST_RUNNER_` env vars. Tests skip themselves if those are unset. Simulator defaults to iPhone 17; override with `PS_TEST_SIM`, falls back to first available iPhone.
- UI tests in `UITests/SmokeUITests.swift` are order-dependent (XCTest runs alphabetically): `testAddHostAndRunExecSnippet` creates the `localbox` host that later tests reuse.
- UIKit-gated sources (`TerminalBridge`, `SSHTerminalView`, VNC views, `TerminalToolbar`) do not compile into macOS `swift test` — they are covered only by UI tests. Terminal screen content is not accessibility-visible (SwiftTerm draws directly), so e2e asserts toolbar presence and absence of error text, not screen text.
- New tests: unit tests go next to the module in `Packages/Core/Tests/<Module>Tests/`; e2e flows go in `UITests/SmokeUITests.swift` with an accessibility identifier on any new tappable control.

## Architecture

Thin app targets, all logic in `Packages/Core` (local SPM package, one library per concern):

- **Models** — value types shared by every target (Host, Snippet, SessionSnapshot, ConfigExport, themes, toolbar keys, VNC config). Watch + Widget depend only on this.
- **KeyKit** — Secure Enclave P-256 device key with software Keychain fallback, OpenSSH public/private key encoding (incl. bcrypt-pbkdf for encrypted keys), password vault.
- **SSHKit** — swift-nio-ssh connection, TOFU known-hosts store, port forwarding, SFTP session, chunked-base64-exec remote file upload. Depends on KeyKit + SFTPKit.
- **SFTPKit** — pure SFTPv3 packet encode/decode (no IO).
- **TmuxKit** — tmux command building and output parsing (session/window/pane listing, dashboard previews, send-keys).
- **MonitorKit** — `TabStatusResolver` (busy/idle/needs-input from screen-text diffs) and `AgentActivityTracker` (agent-finished notifications).
- **ReconnectKit** — auto-reconnect state machine with backoff.
- **TerminalUI** — SwiftTerm wrapper (`SSHTerminalView`, `TerminalBridge`), feed gating, font zoom, pan/scroll tracking.
- **ToolbarUI** — special-keys toolbar, key-sequence encoder, user-editable via `toolbar.json`.
- **VNCKit** — RoyalVNCKit session controller, screen view, pointer math, key combos (ARD auth).
- **LockKit** — Face ID app lock gate.

`App/` is SwiftUI glue: screens, stores, `ConnectionController` (owns SSH lifecycle per host), `SessionMonitor` (5s polling), `WatchRelay` (WatchConnectivity). `WatchApp/` and `Widget/` are separate targets sharing app group `group.com.bl4ko.pocketshell`.

New code goes in a Core module with tests, not in `App/`, unless it is pure UI glue.

## Hard-won gotchas (do not re-learn)

- **Every tmux `set-option` in the attach chain needs an explicit `-t <clone>`**: the chain runs before the client has attached, so an untargeted `set-option` has no current session to resolve against and lands either nowhere (clones never expire — they piled up one per tab ever opened) or on the whole server. Server-wide is destructive: `destroy-unattached on` then kills every detached session and the server exits with it, and `status off` stops tmux-continuum saving, because continuum drives its periodic save off status-line redraws. Order matters too — `destroy-unattached` must be set *after* `attach-session`, since `new-session -d` leaves the clone unattached and tmux destroys it the instant the option lands. Commands after `attach-session` in the same `\;` sequence do run. `cleanupClonesCommand` sweeps leftovers on connect but only kills `*-psh-????????` sessions that are unattached, **grouped**, and >60s old: grouped means the windows are shared with the session they clone so nothing is lost, the age guard avoids racing a tab mid-connect, and a same-named session restored by tmux-resurrect is standalone and holds the only copy of its panes. Verify tmux behaviour on a private socket (`tmux -L pshtest`) — never against a real server.
- **Tab status detection**: `TabStatusResolver` trusts explicit busy/waiting/idle markers; screen diffs are not activity because idle TUIs redraw and busy TUIs can stay static. Tmux polling captures `pane_current_command` with the screen: markerless redraw frames hold the previous status while a foreground process runs, and returning to an interactive shell clears it. Non-tmux tabs retain a one-frame markerless grace. Busy→idle needs 2 consecutive idle frames (`pendingIdle`): Claude Code emits transient idle-marker frames mid-session (survey screen, auto-mode gaps — footer markers like "shift+tab to cycle" and the `\d+% used` ctx statusline read as confident idle while the spinner is absent), which faked finished-unseen dots. Codex idle is detected via `\d+% (context left|used)` footer regex. The running-task/spinner busy marker is `\S…\s*\(\d+[hms]` — it was `\p{L}…` and any task label ending in `)`/digit (e.g. "…(blocked on user Apple portal)… (4m 57s · ↓ 8.5k tokens)") read as confident idle mid-run, faking the finished dot. `pollTabs` feeds `AgentActivityTracker` (and its finished/needs-input transitions) **only non-tmux tabs**, so any per-tab UI signal that must also cover tmux-attached agent tabs has to derive from per-tab status history, never from tracker transitions. The finished-but-unseen blue dot lives in `SessionMonitor.unseenFinished` (keyed `hostID:session:windowIndex`) because `HostTabsScreen` state dies on navigation — it is fed by both the monitor's 15s idle transitions and the 5s tab poll (compare `lastTabStatus`, which ignores nil frames), cleared by viewing the tab or the window going busy, and drives tab-to-front promotion plus the hosts-list blue dot.
- **tmux `window_name` can be a transient placeholder**: automatic-rename rewrites it to `[tmux]` while the pane is in copy mode (any attached client scrolling does it) and `[dead]` after the pane dies. Never persist or display those raw — `Tmux.isPlaceholderWindowName` filters them, `Tmux.windowDisplayName` resolves notification/snapshot names via saved `TabRecord`s (user `name` first, then non-placeholder `windowName`), and `pollTab` refuses to overwrite `tmuxWindowName` with a placeholder. Same trap produced a "bl4ko homeops:4 [tmux]" notification for a window the user had named. Also: a workspace pushed by a device that hasn't polled yet carries nil names — `TabRecord.preservingNames` merges remote over local without wiping known names, else every host open flashes bare tab numbers until the first pane poll. Notifications for the currently-viewed window are suppressed via `SessionMonitor.visibleWindowKey` (set by tab selection/poll, cleared on disappear/background so background notifications still fire).
- **Do not anchor `confirmationDialog` to toolbar chrome on iOS 26**: it renders as an arrow popover pinned to a wrong mid-screen anchor with broken animation, and the stuck presentation can leave nav-bar buttons unresponsive afterwards. The host switcher is a toolbar `Menu` instead — correct anchor, native animation, same buttons for XCUITest.
- **A custom long-press gesture kills `.contextMenu` on the same view**: the tab strip's 0.28s reorder long-press claims the touch before the system context-menu interaction fires, so the tab menu silently died on iPhone. Pair the gesture with a simultaneous longer still-hold (0.55s, context-menu timing) that presents the same actions as a `confirmationDialog`; movement past the reorder threshold cancels it via the `draggingTab` guard. `.contextMenu` stays for Catalyst right-click.
- **Max three trailing toolbar items on iOS**: a fourth goes into the system overflow menu, which on iOS 26 renders its "…" button but does not open — the item is effectively gone (this hid new-tab). Consolidate into the ellipsis `Menu` instead.
- **UI tests run against a real user home**: `uitest.sh`'s throwaway sshd authenticates as the developer, so the app under test reads/writes the real `~/.config/pocketshell/workspace.json` — test runs once pushed 15 throwaway numbered tabs that every attached device then restored. `SessionMonitor.syncWorkspace` is a no-op under `PS_UI_TEST=1`; keep any future per-host remote state behind the same guard.
- **Hidden tabs** live in a ZStack: `allowsHitTesting(false)` blocks touches but NOT first responder. Tab switch focuses the selected TerminalView; `becomeFirstResponder` auto-resigns the old one — never resign-then-become (keyboard dismiss/present jank).
- **Keyboard bottom padding** applies to the ACTIVE tab only and without animation — animated padding reflows SwiftTerm every frame on every tab (lag + PTY resize storms).
- **Clipboard image paste** uploads to remote `/tmp/psh-*.jpg` via chunked base64 exec and inserts the path. Decode MUST be `base64 -d < file` (stdin redirect): BSD base64 on macOS remotes rejects a positional input file with exit 64, and the upload loop surfaces exec failures into the terminal. On Catalyst the toolbar (and its paste button) is compiled out and SwiftTerm's sealed `canPerformAction` gates `paste:` on a string clipboard — image paste only works because Cmd+V is a registered `UIKeyCommand` → `terminalView.paste(nil)`.
- **Mac Catalyst installs must be development-signed**: never install a `CODE_SIGNING_ALLOWED=NO` build. An unsigned replacement loses the Team ID/app-group entitlements and cannot read PocketShell's Keychain SSH credentials. Use `Scripts/install-mac.sh` — Xcode never touches `/Applications`, so rebuilding there leaves the Dock icon on the old binary. Alternating `xcodebuild` and Xcode runs over one DerivedData also breaks signing: Xcode's incremental build re-signs only the embedded frameworks it rebuilt and skips `CodeSign` on `pocketshell.app` itself (its task looks up to date), so the app binary another build wrote stays unsigned and launching fails with "The executable is not codesigned". A clean build is the only way back; the install script detects the unsigned product and does that automatically.
- **RoyalVNC on Mac Catalyst uses our fork**: PocketShell pins `bl4ko/royalvnc` commit `7cd41cf` because upstream 1.1.0 fails to bridge `IOSurface` to `IOSurfaceRef` with Xcode 26.5. The one-line fix is upstream PR #36; keep the fork pin until it is merged and released, then verify signed Catalyst and iOS builds before switching back.
- **The caret must never render on a mid-repaint screen**: a busy TUI (Claude Code under load) writes each repaint in pieces with 80–120ms pauses and the cursor left *visible* mid-frame — tmux relays the pane cursor honestly, so the protocol itself says "cursor visible at the redraw anchor" (column 0 of Ink's dynamic-region top, the same cell every blip). No quiescence window separates a half-finished frame from a finished one; the reliable tell is **how the cursor got there**: finished frames park it with explicit CUP addressing, mid-frame pieces leave it dragged by text/newlines. The fork's `Terminal.cursorAddressed` tracks this and `CaretSettleGate` commits addressed row changes instantly, unaddressed ones only after 250ms of stream quiet; same-viewport-row moves (typing) always commit. During a `.wait` the caret stays painted at the last committed park — hiding it there was itself flicker, because a busy TUI hits the wait path on every repaint piece (~10Hz hide/show at the parked cell). Two prior gates failed: absolute-row stability (scrolling moves the true row every frame while repaints park on one cell — the wrong cell is the stable one) and plain 50ms quiescence (mid-frame pauses exceed it). Verified by replaying captured client streams through the emulator (`CaretStreamReplayTests`, capture via `ptycap` pty wrapper over a throwaway sshd — `pipe-pane` captures the wrong layer, and a locally attached client coalesces tmux's writes; only ssh-hop capture shows real chunking). Do not "fix" a caret complaint by touching `updateCursorPosition`'s coordinates — placement math is fine, timing is what breaks. Caret style is pinned to `.steadyBlock` (`BottomAnchoredTerminalView.cursorStyleChanged` override + initial `setCursorStyle`): SwiftTerm's blink is an opacity fade restarted on every focus/resize and remote DECSCUSR flips styles mid-session — both read as flicker.
- **SwiftTerm uses our fork**: PocketShell pins `bl4ko/SwiftTerm` branch `pocketshell` (rebased onto upstream main, last sync 2026-08-05 at upstream `25ba06f`; rebase again when bumping — upstream now has its own `clearSelection()`, ours is folded into it). It adds public pointer-selection entry points (`startPointerSelection`/`extendPointerSelection`/`selectWord`/`selectRow`/`clearSelection` in `PointerSelection.swift`) so Catalyst mouse drags drive SwiftTerm's native `SelectionService` (renderer-drawn highlight, scrollback-correct, NUL-scrubbed copy), and sets `inlinePredictionType = .no`. Candidate for upstreaming; rebase the branch when bumping SwiftTerm.
- **Touch selection-handle drags must not recompute the grabbed edge from the touch**: the finger lands a cell or two off the handle, so old behavior (`pivotExtend` at `.began`) always ate the first character, and a drag away from both handles reused a stale pivot and collapsed the whole selection. The fork's `grabSelectionHandle`/`dragSelectionHandle` (backed by `SelectionHandleMath`, unit-tested) hit-test both handles with 30pt slop, keep the touch-to-handle cell offset for the whole drag, and leave the selection untouched until the finger moves; the grab anchors must match where `drawSelectionHandle` actually draws — start handle ABOVE the start cell top, end handle BELOW the end cell bottom (end col exclusive) — the first version assumed the opposite and every Catalyst grab (14pt slop < one cell height) fell through to a fresh selection, eating the old one. Selection-starting pan gestures have another trap: `.began` fires only after the ~10pt pan slop, so `location(in:)` is already a cell past the press — anchor at `location - translation(in:)` or the first character is always dropped; non-handle pans no longer modify the selection at all (the app scrolls instead — it yields only on `selectionHandleDragActive`, not `selectionPanActive`). Long press selects the word under the finger. Hardware key repeat is `keyRepeatDelay`/`keyRepeatInterval` (0.3s/30Hz; was 0.4s/10Hz). Toolbar pins all four arrows as plain Buttons with `.buttonRepeatBehavior(.enabled)` — ←/→ used to hide inside the ↑/↓ long-press menus, costing a menu round-trip per keypress, and a `Menu` can't hold-repeat.
- **`SelectionService.pivotExtend` is a no-op without a pivot**: `setSoftStart` activates an empty selection but leaves `pivot` nil, and only SwiftTerm's own `panSelectionHandler` sets it, so every pointer-driven extend silently returned — a drag left two selection handles stacked at the press point and no highlight. The fork's `startPointerSelection`/`selectWord`/`selectRow` set the pivot themselves. Our tap gesture also has to `require(toFail:)` the selection pan: a drag shorter than the tap's 10pt slop fires both, and the tap clears the selection the drag just made.
- **Bulk shell output must stay coalesced**: `ShellDataHandler` accumulates per `channelRead` and yields once per `channelReadComplete`. Without this the PTY delivers ~1KB chunks (5630 for 11MB), each one a MainActor hop + SwiftTerm `feed` that unpauses the CADisplayLink for a full redraw — bulk output (`claude resume` replay) renders as a slow visible scroll. Guarded by `ShellStreamCoalescingTests`.
- **Theme/appearance is enforced at the UIKit window level**: SwiftUI `preferredColorScheme` on Catalyst can fail to apply on the first launch after an Xcode reinstall (stored theme VALUE always reads fine — verified by instrumentation). `AppScreen` additionally sets `overrideUserInterfaceStyle` on all windows on appear and on theme change. Catalyst is also single-instance: launching a second copy (e.g. DerivedData build while /Applications copy runs) starts the process but never connects a UI scene, and direct binary exec / headless lldb launch never get a scene either — test launches need `open` with no other instance running.
- **Catalyst hardware-key handling routes through `UIKeyCommand`, not SwiftTerm**: SwiftTerm's `TerminalView.copy(_:)` is `open` (overridable) but `canPerformAction`/`pressesBegan` are `public` (sealed) — cannot subclass-override them. `pressesBegan` swallows the first key when a marked-text/prediction range is pending (physical Esc needed two presses) — the fork's `inlinePredictionType = .no` removes the prediction source. Register `UIKeyCommand`s (`wantsPriorityOverSystemBehavior = true`) in `TerminalViewController.installControlKeyCommands` — they fire before `pressesBegan`. Cmd+C → `terminalView.copy(nil)` (guarded on `selectionActive`), Esc → send `0x1b` directly. Arrows also go through `UIKeyCommand`: SwiftTerm's `pressesBegan` repeats held keys on a hardcoded 0.4s + 10Hz timer (ignores macOS key-repeat settings), while UIKeyCommand repeats at the system rate; plain arrows keep legacy CSI encodings even under kitty protocol, modified arrows still take `pressesBegan`.
- **tmux window-size battles between devices**: attaching from a second device makes its client the `window-size latest` winner with zero input, shrinking the other device (dotted fill) until that client sends input. A focus-in sequence (`\e[I`) counts as client activity for latest-sizing and is swallowed by tmux even with `focus-events off` (verified: never reaches the pane) — `ConnectionController.nudgeTmuxSizing()` sends it on scene activation and tab switch so the focused device reclaims the size. Scene activation never fires when the device already had focus while the other one attached (or nudged), which leaves the window sized for the absent client: the pane draws into part of the screen only, prompt stranded mid-screen with a garbled column where the wider window's next pane is clamped. So the terminal also nudges on any interaction it can see — pointer hover on Catalyst (key window only), tap and pan on touch — throttled to 2s in `Coordinator.noteUserPresence`. Only safe on tmux tabs; on plain shells the bytes would hit the foreground app.
- **ProxyJump nests a second SSH client inside a direct-tcpip channel**: `SSHConnection(hops:)` dials hop 0 normally, then for every later hop (and the target) opens `.directTCPIP` on the previous channel and adds `SSHChannelDataCodec` → `NIOSSHHandler` → `HandshakeWaiter` in that order — the codec must sit closest to the head so inbound `SSHChannelData` reaches the nested client as `ByteBuffer` and its writes get re-wrapped. The alternative (local port-forward + connect to `127.0.0.1`) is simpler but opens a loopback socket any app on the device can reach and breaks TOFU, which is keyed `hostname:port`. Each hop verifies its own host key; `HostConfig.jumpChain` resolves the chain and guards cycles. Covered by `connectsThroughJumpHost` / `jumpHostRecordsBothHostKeys` against two real sshds.
- **Terminal buffer NUL cells poison copied text**: TUIs skip blank cells with cursor moves, leaving code-0 cells that `translateToString` renders as `\u{0}`; remote shells silently drop pasted NULs (`export TART_HOME` → `exportTART_HOME`). Any text extracted from the buffer must scrub `\u{0}` → space — SwiftTerm's `getText` (native selection copy) and `TerminalBridge.visibleText()` both do.

- **RoyalVNC hands you a black framebuffer before any pixels arrive**: `didCreateFramebuffer` fires during the handshake with a zero-filled buffer (`VNCFramebufferMallocAllocator`), so rendering it publishes a black `image`, the spinner's `image == nil` gate flips, and the user stares at black for the whole first-frame transfer. Only `didUpdateFramebuffer` may call `scheduleRender`; `image == nil` then genuinely means "no frame yet" and the overlay can label the wait. Reconnects also have to clear the old `VNCConnection.delegate` before dropping the reference, or the dead socket keeps publishing state into the live session — `stateDidChange` additionally guards on `connection === controller.connection`.
- **Lowering VNC colour depth is a bandwidth regression, not a saving**: `VNCConnection` strips Tight and ZRLE from the SetEncodings list whenever the pixel format is not 32bpp/24-bit true colour (`TightEncoding.supportsPixelFormat`), so a "low bandwidth = 8/16-bit" preset silently falls back to zlib/hextile and loses Tight's JPEG sub-encoding — the one thing that makes a desktop usable on a weak link. Compression level and JPEG quality are hardcoded at 6 in the library with a `TODO: Make configurable`; changing them means patching the `bl4ko/royalvnc` fork, not the app.
- **Tab labels and the tab strip must survive navigation without the network**: `HostTabsScreen` state dies on every push/pop, so anything not in `AppStore.savedTabs` is re-derived over SSH. `TabRecord` therefore persists `windowName` (populated from the pane snapshot each poll) and `restoreTabs()` runs before `syncWorkspaceNow`, which needs a full handshake and otherwise blocks first paint. Reconcile matches on session + window index, never on the tab `number`: numbers are per-device, so a workspace written by the other phone rebuilt every tab, dropping names and statuses. **Windows are tracked by tmux `window_id` (@N), index is only a fallback**: with `renumber-windows on`, killing any window shifts the indexes, and a device that reattaches by a saved index lands its clone on the wrong window — the poll then faithfully records that wrong window's name and syncs the corruption to every device (two tabs on one window, the real window orphaned). `TabRecord.windowID` + `attachCommand(windowID:)` select by @id (stable across renumber/reorder/rename); `currentTmuxPaneSnapshot` heals index+id from the live clone each poll. In list/snapshot wire formats `window_name` must stay the LAST field — it is the only one that can contain `|`.
- **Theme light/dark is a flag, not an identity check**: chrome used to test `theme == .pocketshell`, which meant a second light theme would get dark-derived chrome (`mixed()` over a light background produces near-white "dark" surfaces with light text). `TerminalTheme.lightChrome` drives `PocketshellTheme`, `AppScreen`'s `overrideUserInterfaceStyle`, and `TerminalToolbar.Palette`. `Palette.dark/darkKey/darkBorder` (tmux-prefix overlay) stay dark in every theme by design.
